# LXGit 游戏协作

LXGit 面向中国大学生游戏开发团队：让第一次接触 Git 的程序、美术和策划也能保存项目版本，与队友同步修改。它作为 LX 工具架内的一个工具运行，管理的是你们的游戏项目。

界面采用白色和浅绿色亮色主题，与 LX 工具架协调。

## 新手先走这条路
1. 从队友提供的 GitHub 地址“下载团队项目”，或添加电脑上已有的游戏项目。
2. 开始工作前“检查队友更新”，再“下载更新”。
3. 在 Unity、3ds Max 或编辑器里正常制作并保存。
4. 在“我修改的内容”里检查文件，选入本次版本，写清做了什么，点击“保存本地版本”。
5. “上传给队友”之后，队友才能下载你的版本。本地保存不等于已经上传。

面板右上角提供“新手指南”。分支、变基、重排等高级功能保留在菜单中，不是新成员每天必须掌握的步骤。

## 游戏项目里的文件
Unity 的 Assets、Packages、ProjectSettings 和 .meta 文件需要由团队共同管理；Library、Temp、Logs 等生成目录通常应忽略。由项目负责人维护 .gitignore，不要因为文件多就直接全部上传。
模型、贴图、音频等二进制大文件可由负责人配置 Git LFS，并提交 .gitattributes。LFS 不会自动解决多人编辑同一场景或模型的冲突，开始修改前仍需与队友沟通。

## 运行要求
Windows x64，LXTools 0.0.1 或更新版本，首次打开时会在后台准备工具私有 PortableGit（含 Git Credential Manager、Git LFS 和 SSH），也可在设置中手动指定已有 git.exe。后台已打包，无需安装 Python。用户文件名、提交原文和 Git 原始诊断保留原文，界面及操作说明为中文。

## 功能
- 新建、添加、克隆和切换仓库；提交者信息、远程地址和忽略规则。
- 改动列表、文本差异、整文件暂存、已跟踪文本逐行勾选部分暂存（新增和删除按整文件）、图片前后对比、提交和修订最近提交。
- 分支比较、文件历史、GPG 签名设置、外部编辑器打开；分支创建/切换/重命名/删除、合并、压缩合并、变基、拣选、反向提交、保留文件的重置。
- 提交历史与操作恢复日志、压缩和重排连续提交（自动创建恢复分支）、储藏与恢复、标签管理。
- 获取、快进拉取、变基拉取、推送、带租约的强制推送。
- 冲突采用一方、手工解决后标记、继续或中止合并/变基/拣选。
- Git LFS 初始化、跟踪和下载；子模块递归初始化与更新。
- Git Credential Manager 浏览器登录，支持配置 Enterprise 域名；GitHub 账号和仓库列表、个人或组织仓库创建、派生、克隆、拉取请求列表/检查状态/创建草稿/检出、浏览器打开仓库。

## 使用
1. 添加本地仓库或克隆远程仓库。
2. 新仓库先设置姓名和邮箱。选择改动文件并暂存，填写说明后提交。
3. 需要同步时配置 origin，使用 GitHub 登录后推送。创建 GitHub 仓库和推送都需明确点击。
4. 冲突时先检查文件，在文件菜单采用一方或在编辑器手工修复后暂存，再从分支菜单继续。
5. 删除分支只允许已合并分支。丢弃操作只处理已跟踪文件的未暂存修改，不删除未跟踪文件。

## 当前限制
当前为 0.0.6 版本，尚不能宣称与 GitHub Desktop 全功能等价。未实现拖动重排提交、后台定时自动 fetch、提交图可视化和无障碍完整审计。GitHub Enterprise、组织仓库创建、GPG 签名设置、外部编辑器和 PR 检查状态已提供入口，但仍需对应账号或环境实测。文本差异最多显示 2 MB，历史一次加载 200 条，PR 一次加载 100 条。用户名/提交说明以及底层 Git 技术诊断不自动翻译。

长任务在独立后台进程运行。离开面板会停止后台任务；不要在克隆/推送期间关闭工具架，关闭后请检查仓库状态再继续。凭据仅通过系统 Git 凭据助手获取，不写入工具设置。仓库不可信 hooks/filters 和本地 Git 配置属于 Git 自身执行环境，工具不隔离它们。

## 发行
工具只通过 GitHub Release 分发，附件名 LXTool-package.zip。在 LX 工具架中扫描作者仓库，下载“LXGit 游戏协作”，从“我的工具”打开。源码和版本记录：https://github.com/gd-dd/LXGit 。

## 0.0.6 验证范围
工具私有 Git 下的 22 项隔离仓库回归、31 项运行时管理测试及 9 项面板准备测试通过。已验证中文空格路径的真实签名校验、解包、组件检查、取消清理，以及公开 LXTools 0.0.8 冻结客户端下的离线准备、关闭和重开。首次官方下载和最终候选的离线复用分别留有证据；正式发行后的匿名安装、全新环境首次下载及当前用户窗口验收单独记录，不用合成测试安装冒充用户安装。

## 工具私有 Git
默认首次打开自动下载固定官方 PortableGit 2.56.1.windows.1（约 60 MB）。界面显示下载、校验、解压与组件检查，可取消并重试。网络中断或校验失败不会标为就绪，也不会偷偷使用系统 Git。只有用户显式选择的 Git 会覆盖私有运行环境。

正式安装放在 `LXGit--1432888469/runtime/git/2.56.1.windows.1`，位于 `versions` 旁；源码开发放在仓库 `runtime/git`。完整 PortableGit 含较深的目录，工具安装路径过长时会明确提示改用较短位置或手动 Git，避免反复下载后解包失败。旧式安装布局不自动向父目录写入，需通过新版工具架规范安装或手动选择 Git。准备完成后离线复用，不在每次打开时检查最新版。Git/LFS/GCM/SSH 的 PATH 仅对后台子进程生效，不修改系统 PATH、注册表或 Git 安装。

官方包先核对固定大小、SHA-256、有效数字签名，再在隔离临时目录运行官方静默自解压并验证组件。临时文件在失败/取消时清理；异常强制关闭留下的临时目录会在下次准备持锁清理。已损坏的运行时隔离保存，验证新运行时成功后才启用。设置中的“使用工具管理的 Git / 修复检查”会重新验证；需要手动清理缓存时请先关闭所有 LXGit 面板，只删除该容器的 runtime/git，下一次打开会重新准备。删除工具的单个 versions 目录不会删除共享 Git。

官方分发与许可证：https://github.com/git-for-windows/git/releases/tag/v2.56.1.windows.1 。保留 PortableGit 内的 LICENSE.txt、ReleaseNotes.html 和组件许可文件；LXGit直接从官方获取完整包，不重打包分发 Git。GitHub Desktop 全功能对齐、私有远端与 Enterprise 环境仍受“当前限制”约束。
